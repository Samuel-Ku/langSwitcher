LangSwitcher — бесплатный проект с открытым исходным кодом под [лицензией MIT](https://github.com/reg2005/langSwitcher/blob/main/LICENSE). Контрибьюты любого рода приветствуются!

## Сообщение об ошибках

Нашли баг? [Создайте issue на GitHub](https://github.com/reg2005/langSwitcher/issues).

### Что включить в баг-репорт

1. **Описание** — что произошло и что ожидалось
2. **Шаги воспроизведения** — как вызвать баг
3. **Версия macOS** — например, macOS 15.2 Sequoia
4. **Версия LangSwitcher** — видна в Настройках → О программе
5. **Раскладки клавиатуры** — какие раскладки включены
6. **Журнал преобразований** — экспортируйте через Настройки → Журнал → **Экспорт JSON** и приложите файл

::callout{icon="i-lucide-scroll-text" color="blue"}
**Приложите журнал преобразований!** Он содержит исходный текст, результат, раскладки и время — это значительно ускоряет отладку. Экспортируйте через **Настройки → вкладка Журнал → Экспорт JSON**.
::

### Пример баг-репорта

```
**Баг:** Текст некорректно преобразуется для немецкой раскладки

**Шаги:**
1. Включить немецкую (QWERTZ) и английскую (QWERTY) раскладки
2. Набрать «hallo» в английской раскладке
3. Нажать ⇧⇧
4. Ожидалось: «hallo» (корректный немецкий) — Получено: «jzllo»

**macOS:** 15.2
**LangSwitcher:** 1.0.0
**Раскладки:** U.S., German

**Журнал приложен:** conversion-log-2026-03-01.json
```

## Контрибьютинг кода

### Начало работы

1. Сделайте форк [репозитория](https://github.com/reg2005/langSwitcher)
2. Клонируйте форк
3. Активируйте pre-commit верификатор pbxproj (один раз для каждого клона):

```bash
./scripts/install-hooks.sh
```

::callout{icon="i-lucide-shield-check" color="blue"}
Хук версионирован в `githooks/`, но git учитывает его только через локальную настройку `core.hooksPath`, которая не клонируется. Скрипт идемпотентен — безопасно запускать повторно. Проверить, активен ли хук, можно в любой момент: `scripts/install-hooks.sh --status`. Чтобы пропустить проверку для одного коммита, используйте `git commit --no-verify`: CI в любом случае запускает тот же верификатор.
::

4. Откройте `LangSwitcher.xcodeproj` в Xcode
5. Внесите изменения
6. Запустите тесты:

```bash
xcodebuild test \
  -project LangSwitcher.xcodeproj \
  -scheme LangSwitcher \
  -destination 'platform=macOS' \
  CODE_SIGN_IDENTITY="-" \
  CODE_SIGNING_REQUIRED=NO \
  CODE_SIGNING_ALLOWED=NO
```

7. Закоммитьте и запушьте
8. Откройте Pull Request

### Auto-CI поллер (для форков)

GitHub не запускает воркфлоу по push в форках, пока кто-то один раз не откроет вкладку Actions и не нажмёт «I understand my workflows, go ahead and enable them». У этого флага нет REST API, поэтому пуши доходят, но триггеры `on.push` не срабатывают. [scripts/auto-ci-dispatch.sh](https://github.com/reg2005/langSwitcher/blob/main/scripts/auto-ci-dispatch.sh) обходит это: `install` регистрирует LaunchAgent, который каждые 60 секунд проверяет дефолтную ветку форка и запускает воркфлоу `Build & Release` для коммитов без ранов (идемпотентно — перезапуски никогда не дублируют dispatch).

```bash
scripts/auto-ci-dispatch.sh install     # зарегистрировать LaunchAgent
scripts/auto-ci-dispatch.sh status      # отчёт только для чтения: загружен? последний dispatch? недавние раны (exit 0/1)
scripts/auto-ci-dispatch.sh uninstall   # удалить агент
```

::callout{icon="i-lucide-users" color="blue"}
**Это нужно только форкам с ещё выключенными триггерами.** Если пуши уже сами запускают CI на вашем форке, поллер не нужен. После одноразового включения на вкладке Actions удалите его — push-триггеры заработают сами. Жизненный цикл поллера покрыт CI-самотестом (`scripts/test-auto-ci-dispatch.sh`, заглушка вместо `gh`, без сети).
::

### Правила

- **Все тесты должны проходить** перед отправкой PR
- **Новые фичи требуют тестов** — добавьте юнит-тесты для нового функционала
- **Следуйте существующему стилю** — чистый Swift, без внешних зависимостей
- **Локализация** — все новые строки интерфейса через `LocalizationManager.shared.t("key")`, добавляйте в оба файла `Strings_en.swift` и `Strings_ru.swift`

### Добавление новой раскладки

1. Создайте новый `LayoutCharacterMap` в `Sources/Services/LayoutMapper.swift`
2. Добавьте карту символов между новой раскладкой и английской
3. Зарегистрируйте карту в `allMaps`
4. Добавьте тесты в `LangSwitcherTests/LayoutMapperTests.swift`
5. Обновите документацию
