LangSwitcher — безкоштовний проєкт з відкритим кодом під [ліцензією MIT](https://github.com/reg2005/langSwitcher/blob/main/LICENSE). Внески будь-якого роду вітаються!

## Повідомлення про помилки

Знайшли баг? [Створіть issue на GitHub](https://github.com/reg2005/langSwitcher/issues).

### Що включити в баг-репорт

1. **Опис** — що сталося і що очікувалося
2. **Кроки відтворення** — як викликати баг
3. **Версія macOS** — наприклад, macOS 15.2 Sequoia
4. **Версія LangSwitcher** — видна в Налаштуваннях → Про програму
5. **Розкладки клавіатури** — які розкладки ввімкнено
6. **Журнал перетворень** — експортуйте через Налаштування → Журнал → **Експорт JSON** і додайте файл

::callout{icon="i-lucide-scroll-text" color="blue"}
**Додайте журнал перетворень!** Він містить вихідний текст, результат, розкладки та час — це значно пришвидшує налагодження. Експорт: **Налаштування → вкладка Журнал → Експорт JSON**.
::

### Приклад баг-репорту

```
**Баг:** Текст некоректно перетворюється для німецької розкладки

**Кроки:**
1. Увімкнути німецьку (QWERTZ) та англійську (QWERTY) розкладки
2. Набрати «hallo» в англійській розкладці
3. Натиснути ⇧⇧
4. Очікувалося: «hallo» (коректна німецька) — Отримано: «jzllo»

**macOS:** 15.2
**LangSwitcher:** 1.0.0
**Розкладки:** U.S., German

**Журнал додано:** conversion-log-2026-03-01.json
```

## Внесок коду

### Початок роботи

1. Зробіть форк [репозиторію](https://github.com/reg2005/langSwitcher)
2. Клонуйте свій форк
3. Активуйте pre-commit верифікатор pbxproj (один раз для кожного клону):

```bash
./scripts/install-hooks.sh
```

::callout{icon="i-lucide-shield-check" color="blue"}
Хук версіонується в `githooks/`, але git враховує його лише через локальну конфігурацію `core.hooksPath`, яка не клонується. Скрипт ідемпотентний — безпечно запускати повторно. Перевірити, чи хук активний, можна будь-коли: `scripts/install-hooks.sh --status`. Щоб пропустити перевірку для одного коміта, використовуйте `git commit --no-verify`: CI запускає той самий верифікатор незалежно.
::

4. Відкрийте `LangSwitcher.xcodeproj` у Xcode
5. Внесіть зміни
6. Запустіть тести:

```bash
xcodebuild test \
  -project LangSwitcher.xcodeproj \
  -scheme LangSwitcher \
  -destination 'platform=macOS' \
  CODE_SIGN_IDENTITY="-" \
  CODE_SIGNING_REQUIRED=NO \
  CODE_SIGNING_ALLOWED=NO
```

7. Закомітьте та запуште
8. Відкрийте Pull Request

### Auto-CI поллер (для форків)

GitHub не запускає воркфлоу на push у форках, доки хтось один раз не відкриє вкладку Actions і не натисне «I understand my workflows, go ahead and enable them». У цього прапорця немає REST API, тож push-и доходять, але тригери `on.push` ніколи не спрацьовують. [scripts/auto-ci-dispatch.sh](https://github.com/reg2005/langSwitcher/blob/main/scripts/auto-ci-dispatch.sh) обходить це: `install` реєструє LaunchAgent, який кожні 60 секунд перевіряє дефолтну гілку форка та запускає воркфлоу `Build & Release` для комітів, у яких ще немає рану (ідемпотентно — перезапуски ніколи не задублюють dispatch).

```bash
scripts/auto-ci-dispatch.sh install     # зареєструвати LaunchAgent
scripts/auto-ci-dispatch.sh status      # звіт лише для читання: завантажений? останній dispatch? недавні рани (exit 0/1)
scripts/auto-ci-dispatch.sh uninstall   # видалити агент
```

::callout{icon="i-lucide-users" color="blue"}
**Це потрібно лише форкам з ще вимкненими тригерами.** Якщо push-и вже самі запускають CI на вашому форку, поллер не потрібен. Після одноразового натискання «enable» на вкладці Actions вашого форка видаліть його — push-тригери запрацюють самостійно. Життєвий цикл поллера покритий CI-самотестом (`scripts/test-auto-ci-dispatch.sh`, заглушка замість `gh`, без мережі).
::

### Правила

- **Усі тести мають проходити** перед надсиланням PR
- **Нові функції потребують тестів** — додавайте юніт-тести для нового функціоналу
- **Дотримуйтеся наявного стилю** — чистий Swift, без зовнішніх залежностей
- **Локалізація** — усі нові рядки інтерфейсу через `LocalizationManager.shared.t("key")`, додавайте до `Strings_en.swift` та інших файлів `Strings_xx.swift`

### Додавання нової розкладки

1. Створіть новий `LayoutCharacterMap` у `Sources/Services/LayoutMapper.swift`
2. Додайте мапу символів між новою розкладкою та англійською
3. Зареєструйте мапу в `allMaps`
4. Додайте тести в `LangSwitcherTests/LayoutMapperTests.swift`
5. Оновіть документацію
